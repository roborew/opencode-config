# Execution-lane permission posture (broad allow + deny-list)

Execution subagents (`developer`, `frontend-dev`, `ux-dev`, `senior-dev`, `scribe`, `code-review`, etc.) use `bash: "*": allow` with explicit dangerous-command denies and `edit` denied on `~/.config/opencode/**`. This supports unattended orchestration overnight. **Architect** is read-only (`edit: deny`) with **allow-by-default bash** and the same class of mutation/redirect/package denies — so `setup-project`, `opencode-run spec fanout`, `gh`, and `setup-project --check-only` run without prompts; local file writes stay on **scribe** / **stack-bootstrap** via Task. **Orchestrate** has `bash: false`: bootstrap env shell goes to **`worktree-env`** / **`preflight`**; GitHub/stage shell goes to **`developer`**.

**Considered:** Granular per-command allowlists for architect and execution agents. Rejected — whitelists blocked documented setup-project commands (`bash -lc`, `yq`, `gh … -q`) and caused repeated shell failures when `ask` could not be approved mid-session.

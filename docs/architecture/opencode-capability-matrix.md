# OpenCode capability matrix

| Capability | Owner agent | Skill(s) | Skill load default | Artifact / output | Gate |
|------------|-------------|----------|-------------------|-------------------|------|
| Feature / plan | `architect` | `grill-me`, `to-tickets`, `issue-expand` (spec or impl), `wayfinder` | Parent: sub-skills by mode; **Task** children: `load: full`, `minimal`, or `auto` per [`agents/architect.md`](../../agents/architect.md) | GitHub issues (`feature:<slug>` + `opencode-task-yaml`) via `scribe` / `bin/publish-targeted-issue` | User → `orchestrate` |
| Stage execution (outer loop) | `orchestrate` | `orchestrate` | Parent: `load: full` once per session; selects work, creates feature worktree, kicks coder sessions per ticket (worktree-manager + session_notify), gates PR approval, merges + cleans up, kicks the feature coder (`feature-review`), merges the feature PR on human approval, hands back to spec `feature-complete`. Never verifies code-review/CodeRabbit evidence — terminal reports + human approval are its only gates | Develop orchestrator record (lifecycle log) + `feature_report:` parsed from the feature coder | feature-mode code-review inside `feature-review` |
| Stage execution (inner loop) | `coder` | `ticket-lifecycle` | Parent: `load: full` on first message; runs §0 Bootstrap (brief file + GitHub), silent preflight, every `stages[]` entry (test-writer RED → owner GREEN → per-stage code-review), final-gate full suite via `docker-compose.test.yml`, local CodeRabbit pre-flight (`ticket_coderabbit_preflight`), sub-PR + stabilization, terminal `ticket_report:` + `session_notify` | `ticket_report:` issue comment + `session_notify` (best-effort) | `code-review` per-stage (focused) + `all_stages: true` full-suite gate |
| Feature verification + sign-off | `coder` (feature worktree) | `feature-review` | Parent: `load: full` on first message (kicked by orchestrator after every ticket merges into `opencode/feat-<slug>`); full-suite `code-review`, PR-side CodeRabbit gate (medium/hard), difficulty gates (medium → `review`; hard → `senior-dev scheduled_review`), docs (`document` + `scribe`), `state:done` on every ticket, feature PR via `feature-finish-pr.sh`, bounded stabilization, one terminal `feature_report:` + `session_notify` | `feature_report:` issue comment on PRD parent + `session_notify` (best-effort) | full-suite `code-review` APPROVED + PR-side CodeRabbit `PASS` + difficulty gate + docs + all tickets `state:done` — all inside the feature coder loop; the orchestrator only reads the terminal report |
| Worktree env copies (opt-in) | `worktree-env` | `worktree-env` | Parent: `load: full` once per bootstrap; trust canonical evidence | Copy report with `wt_root`, `main_root`, per-file `is_regular_file` | `preflight` (verify only) |
| Env bootstrap / repair (opt-in) | `preflight` | `preflight` | Parent: `load: full` on preflight Task | `Ready` or one `recommended_env_fix`; repair pass for deps/runtime/indexing | `orchestrate` sets `env_gate_passed` |
| Backend / generic code | `developer` | `developer` | `auto` (tiered triggers in agent; parent overrides) | Completion report | `code-review` |
| Frontend | `frontend-dev` | `frontend-dev` | `auto` | Completion report | `code-review` |
| HTML prototype | `ux-dev` | `ux-dev` | `auto` | `.prototype/<slug>/` | `code-review` |
| Review (planning) | `review` | `review` + optional `security-reviewer`, `performance-reviewer`, `doc-reviewer` | `auto` (effective `load: full` for `review`; specialists default `load: full`) | Review markdown to parent | Architect + `scribe` |
| CodeRabbit — local pre-flight (per ticket) | `coder` (ticket session) → `review` | `code-review` (+ `review` on `load: full`) | Parent: `load: full` on CodeRabbit Task; once per ticket after the final-gate full suite, before the sub-PR opens (`ticket_coderabbit_preflight`) | `CODERABBIT_PREFLIGHT` + finding inventory; findings applied as fix-now suggestions by the coder | Correctness + obvious bugs + risky changes only; `coderabbit review --agent --base opencode/feat-<slug>`; narrow the rule set further if it duplicates the PR-side gate |
| CodeRabbit — PR-side gate (feature sign-off) | `coder` (feature coder) → `review` | `code-review` (+ `review` on `load: full`) | Parent: `load: full` on CodeRabbit Task; **exactly once** per feature (`feature-review` medium/hard) | `CODERABBIT_GATE` + full finding inventory + per-item local resolutions; feature completion summary | After last code-review / queue exhausted; `coderabbit review --agent --base develop` by default; before final push/PR — **not** per issue and **not** after remediation |
| Evidence check | `code-review` | `code-review` | `auto` | Verdict + evidence | Coder (ticket or feature mode) |
| Docker compose build/test (Sysbox sibling, verification-only) | `developer`, `frontend-dev`, `code-review` (probe: `preflight`); **`orchestrate` instructs Tasks only — does not load the skill** | `docker-sandbox` | Load when Compose/Docker is needed (`sandbox: preferred\|required` from parent, compose in `test_commands`, or preflight `sandbox: ready` + compose file). Soft-skip when unavailable unless required. Not Cloudflare Workers Sandbox. | `sandbox exec` logs | `OPENCODE_SANDBOX_ENABLED`; rebuild OpenCode image after `CONFIG_REF` change |
| Docs generation | `document` | `document` | `auto` | Content to `scribe` | Architect or feature coder |
| Ship / hotfix / TDD | (user-chosen agent with skill allowed) | `ship`, `hotfix`, `debug-fix`, `tdd` | User-chosen | Git / PR | User confirms each step |

Other read-only specialists (`debugger`, `refactor`, `designer`, `strategist`, `senior-dev`, `mentor`, `vision`, `scribe`) define **Execution readiness** and **Auto-load triggers** in their agent files; parents still pass `load: full|minimal|auto` on every Task. **`worktree-env`** and **`preflight`** are narrow startup subagents (bash + allow-listed skills only; no app-code edits).

## Preserved strengths

- Per-agent model routing in `opencode.json`.
- MCP: `mcpjungle` and `claude-context` (command path unchanged). MCPJungle manages Context7, Cloudflare API, Cloudflare Docs, and `docs-mcp-server` upstream authentication. Narrow Cloudflare skills: `cloudflare`, `wrangler`, `workers-best-practices` (from [cloudflare/skills](https://github.com/cloudflare/skills)).
- `strategist`, `preflight`, architect plan/review split.

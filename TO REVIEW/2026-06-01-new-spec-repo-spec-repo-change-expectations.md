## Question reported

```text

```

The user observed a commit and push in the spec repo (`chore: sync mycelia-tree-spec target repos`, `docs/agents/repos.md` changed `+4 / -2`) and asked:

> Would I expect to see any changes in the spec repo when running this task?

---

## Short answer

**Sometimes yes, sometimes no.**

- **Yes (commit + push):** When regenerated `docs/agents/repos.md` (or anything else picked up by `git add -A`) differs from the last commit.
- **No (no new commit):** When the target-repo list and file content are already in sync — the script prints `Spec repo already up to date.` and skips the commit step.

Other steps in the script (label seeding, branch protection, linking implementation repos) may still run even when the spec repo has **no new git changes**.

---

## How `new-spec-repo` decides spec-repo file changes

### 1. Target discovery

From the parent directory (e.g. `mycelia-tree/`), the script discovers sibling git folders:

- Skips the spec folder itself (`${APP}-spec`, e.g. `mycelia-tree-spec`).
- Skips dot-directories.
- Requires a `.git` directory.

Explicit targets can be passed on the command line instead of auto-discovery.

### 2. Always regenerates routing config

The script **always overwrites** `docs/agents/repos.md` with the current target list:

```bash
{
  echo "# Generated by new-spec-repo."
  echo "# This file is routing configuration; rerunning the script replaces this list."
  echo "repos:"
  for target in "${TARGETS[@]}"; do
    full="$(normalize_repo "$target")"
    echo "  - name: ${full}"
    echo "    role: target"
  done
} > docs/agents/repos.md
```

Local folder names are normalized to `GH_ORG/repo` (default org: `roborew`).

### 3. Commit only if the index differs

```bash
git add -A
if git diff --cached --quiet; then
  echo "Spec repo already up to date."
else
  git commit -m "chore: sync ${SPEC_NAME} target repos"   # existing repo path
fi
git push -u origin HEAD || true
```

**Implications:**

| Trigger | Typical spec-repo git change |
|---------|------------------------------|
| New sibling repo cloned under parent | Yes — new entry in `docs/agents/repos.md` |
| Repo removed or renamed locally | Yes — list shrinks or names change |
| Same siblings, same normalized names, same file content | No — “already up to date” |
| First-time bootstrap (`CREATED_SPEC=true`) | Yes — full scaffold + `chore: bootstrap …` commit |
| Unrelated dirty files in spec repo | Possibly — `git add -A` stages **all** changes, not only `repos.md` |

## Side effects that do **not** require spec-repo file changes

These steps run every time (subject to tooling/permissions) but do not necessarily modify tracked files in the spec repo:

| Step | Where it applies | Spec-repo git impact |
|------|------------------|----------------------|
| Label seeding from `.github/labels.yml` | Spec repo + each target in `repos.md` | None (GitHub API only) |
| Branch protection on default branch | GitHub repo settings | None |
| `link-spec-repo` in each local impl repo | `mycelia-tree-api`, `mycelia-tree-web` | None in spec repo; may touch impl-repo local config |
| Optional GitHub Project / `LABEL_SYNC_PAT` reminders | Operator follow-up | None |

From the run:

```text
Linking mycelia-tree-api...
bin/feature-context already exists — not overwriting.
Linking mycelia-tree-web...
bin/feature-context already exists — not overwriting.
```

Impl repos were already linked; `feature-context` was not overwritten.

## When to expect **no** spec-repo commit on rerun

Rerun from the same parent folder with the same sibling repos and stable `GH_ORG` normalization. If `docs/agents/repos.md` regenerates to identical content, expect:

```text
Spec repo already up to date.
```

Label seeding and linking may still produce console output (e.g. label “created” with `--force`, or “already exists” for links).

## Operator checklist

```bash
# From app parent (siblings: mycelia-tree-spec, mycelia-tree-api, mycelia-tree-web, …)
cd /path/to/mycelia-tree
~/.config/opencode/bin/new-spec-repo

# Inside spec repo — did sync produce a commit?
cd mycelia-tree-spec
git log -1 --oneline
git show --stat HEAD    # expect docs/agents/repos.md when targets changed

# Confirm routing list
cat docs/agents/repos.md
```

**Before rerun:** If the spec repo has **uncommitted changes** you care about, commit or stash first — existing-repo sync refuses to proceed when the working tree is dirty (except on the brand-new create path).
